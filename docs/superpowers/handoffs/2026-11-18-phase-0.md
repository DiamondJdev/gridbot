## Owner decisions

These are settled and already written into the spec or plan.

- Visitors only watch. They have no control of the simulation, and the gateway accepts no visitor commands.
- Test-only scenario loading and stepping need `GRIDBOT_TEST_CONTROL=1` on the gateway. Production never sets it.
- ROS scenario tests run in lockstep through `/sim/tick_done`.
- Reference stacks run as shadows under `/reference`, publish no transforms and can't move the robot. Comparisons use single-lidar rigs.
- Scenarios own the map, rig, mode and seed. Run configs may override them, and `expect` thresholds apply only when nothing is overridden.
- Wrapper nodes stay plain ROS nodes until Phase 9.
- In Phase 0, `gateway`, `ui` and `e2e` are placeholders with one test each. The gateway server, UI app, Vite and Playwright arrive in Phase 1.
- `docs/runtimes.md` and `docs/sensors.md` stay in Task 8. The owner kept them after a suggestion to defer them.

Two risks are deferred on purpose, so don't solve them in Phase 0:

- Compute load. The Phase 5 Pi check won't cover SLAM or the reference stacks, so the plans for Phases 6, 7 and 9 should repeat it.
- Bandwidth per visitor. The owner will handle this if it becomes a real problem.

## Already tested

Throwaway prototypes confirmed these:

- The uv workspace installs both packages.
- Ruff bans `random` in `core`, and import-linter rejects `rclpy` and `socket`, including from a temporary package copy.
- `pythonpath = ["scripts"]` fixes the docs checker import.
- The ROS image builds with `--break-system-packages`, and `colcon test` passes for a message package and an `ament_python` package.
- Prettier passes with the planned `.prettierignore`.
- The three placeholder TypeScript packages pass tests and type checks, and the gateway builds and prints its version line.

Not tested: the gateway Dockerfile, the Compose file, `scripts/e2e_compose.sh`, `scripts/step.sh`, the docs checker, ESLint, the pre-commit hooks and the GitHub workflows.

## Likely snags

- The plan's `.gitignore` omits `__pycache__/`. This agent environment sets `PYTHONDONTWRITEBYTECODE=1`, which can hide the problem. Add the entry in Task 1, because `.pyc` files were staged by `git add core runner` when the variable was unset.
- The sample Python tests have no type annotations. If pyright strict includes test folders, they will need them.
- `docker compose down` may skip services behind profiles unless the script passes those profiles. Task 6 expects no containers left behind.
- The spec's workflow requires a `code-review` pass on the branch diff before the PR, and the plan has no step for it. Run it after Task 9, fix the findings and rerun `make verify-all`.
- The spec's `make verify` describes the finished project. For Phase 0, follow the table in plan Task 7.
